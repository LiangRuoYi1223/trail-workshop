# 徒步路线 → 可打印三维地形：开发流程 v0.1

日期：2026-10-08。状态：规划草案，供后续逐轮修改；尚未运行开源项目或生成实际路线样品。

## 1. 目标与第一版范围

用户在网页导入从两步路导出的 GPX，程序自动取得路线周边高程，生成具有平底、实体山体和突出路线的可打印模型，提供预览和下载。

实施顺序已经确认：先个人验证，再接入《川衡网页设计》，最后开放给协会成员。

第一版主要还原参考图里的“山地起伏＋清晰路线”。山体和路线分色是后续可增加的输出能力；照片中的植被、雪线、水体和纹理需要另行定义颜色分区或上色工艺。

首个可用版本包括：

- GPX 导入、分段识别和异常提示。
- 自动推荐包含完整路线的地形范围，并允许调整范围与朝向。
- 自动高程获取；支持本地 GeoTIFF 作为数据源替代。
- 模型长边、地形垂直放大、底座厚度、路线宽度和凸起高度。
- 可旋转、缩放的三维预览。
- 输出一个山体、路线、底座连成实体的 STL。
- 输出几何检查结果、实际毫米尺寸和生成参数，便于复现。

第二轮增加一份包含独立地形与路线实体的 3MF，支持在切片软件中分配耗材。通用 3MF 与某款切片软件的完整打印工程不同，下载后仍需选择打印机、耗材和切片参数。

注意两个 TrailPrint 是不同项目。与“两步路导出 GPX → Terrain_Main.stl＋Trail_Line.stl”描述最接近的是 baozjj 的项目，不能与 EmGi 的 Blender 插件混淆。

优先候选的需要改造之处：

- [架构说明](https://github.com/baozjj/TrailPrint-3D/blob/main/ARCHITECTURE.md) 把 DEM、网格、STL 和文件操作放在 Electron 主进程。需要将 IPC、桌面文件对话框、Electron 缓存路径替换成网页服务接口。
- 已检查的 GPX 实现使用正则并合并分段，需改成可靠的 XML 解析，保留段间中断，防止在暂停或缺失位置间生成错误连线。
- 已检查的路线网格断言主要检查三角形数量，不能当作闭合实体的证明；必须对最终导出文件增加水密、退化面和连通检查。
- 复用代码保留其许可与来源记录；其他候选若进入实现，再按实际复制范围核查其许可文件与依赖。

辅助候选：[mapscad](https://github.com/because-why-not/mapscad) 有浏览器地形建模及 STL/3MF 输出。其 LICENSE 为 BSD-3-Clause，而已查看的 package.json 声明 MIT；进入复用前需要明确许可证信息，当前不把它作为已定核心。

## 3. 输出格式决策

| 格式 | 计划角色 | 说明 |
| --- | --- | --- |
| STL | 第一阶段打印交付、长期兼容输出 | 一个闭合实体，按毫米导出；STL 本身没有可靠单位声明，说明文件和导入验证均按毫米处理 |
| 3MF | 第二阶段起的主要下载格式 | 一份文件容纳多个实体、单位及相关属性，便于地形与路线分色；需验证目标切片软件的兼容性 |
| GLB 或前端网格 | 网页预览 | 从相同生成参数派生；不能把视觉模型直接当作通过打印检查的文件 |
| STEP/STP | 可选后续能力 | 适合 CAD 工作流；地形主要由大量三角面表示，转换为 CAD 实体是额外工作，不作为第一版完成条件 |

格式依据：[3MF Consortium FAQ](https://3mf.io/resources/faq/)；网格转 CAD 需要额外构造形状/实体，见 [FreeCAD 官方说明](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Part_ShapeFromMesh.md)。

## 4. 程序内部处理流程

### 4.1 导入与校验

1. 读取 GPX 的经纬度、轨迹段及可选海拔；记录来源和轨迹名称。
2. 支持规范 GPX 1.0/1.1；区分 track、route 与孤立 waypoint，不把 waypoint 自动连成徒步路线。
3. 校验坐标范围、空轨迹、重复点、异常跳点和多个轨迹段。
4. 给出建议范围；保留真实断点，异常修正可预览，不默默修改实际路线。

### 4.2 地形范围与高程

1. 从轨迹计算包含路线的范围，并在四周添加适量余量。
2. 允许用户调整取景和旋转；检查裁剪是否遗漏路线。
3. 获取对应区域 DEM，记录数据集、水平间距、坐标基准和垂直基准。
4. 将轨迹和 DEM 转到统一米制坐标；中国地图显示坐标与导出坐标是否一致，以样品检查。
5. 识别 NoData、下载失败和未覆盖区域；数据不足时提示重试、换数据源或导入本地 DEM，不把网络失败填成虚构山体。
6. 平滑与重采样服务于网格和打印效果；增加网格密度不会增加原始 DEM 的真实地形细节。

高程来源采用可替换接口。个人验证阶段可使用个人 OpenTopography Key 或公开 DEM 数据；成员版需要选择适合多人服务的数据访问方式。OpenTopography 明确限制共享个人 Key、通过应用绕过一人一 Key，因此不能把一个个人 Key 隐藏在服务器后就视为可供所有成员共用。[数据服务原文](https://opentopography.org/developers)

### 4.3 构造山体实体

1. 依据选区和打印长边建立水平缩尺，保持 X/Y 比例一致。
2. 使用区域相对高差设置山体高度，支持可见的垂直放大倍数。
3. 生成山体表面三角网格、侧壁及封闭平底，确保有实际底座厚度。
4. 记录最终毫米尺寸、地形比例、垂直放大及原始数据分辨率。

### 4.4 将路线变成可打印几何

1. 对路线进行保形重采样，从用于山体的同一高度场取得表面高度。
2. 在模型毫米单位下生成具有宽度和厚度的凸起实体，连接山体。
3. 检查近邻折返、往返重叠、自交、陡坡与裁剪边界。
4. 单色模式将山体、路线和底座合成闭合实体。
5. 分色模式生成独立且可验证的路线实体，明确与山体的接口，避免两种材料出现未处理的体积冲突。

路线必须由真实几何构成，单纯给预览模型画一条红线不能作为打印输出。

### 4.5 预览、检查与导出

1. 预览显示取景、尺寸、路线宽度、凸起高度和山体放大效果。
2. 用较轻的派生网格提升网页响应，最终打印网格使用明确的输出精度。
3. 检查闭合、法线、退化面、自交、非预期孤立部件、尺寸和最薄结构。
4. 用目标切片软件导入实际导出的文件，检查毫米尺寸、路线连续性、分色和分层效果。
5. 生成模型、预览图、参数和检查报告；提供有权限的下载。

## 5. 适合接入川衡网站的结构

以当前源代码为准，《川衡网页设计》已有 React＋Vite＋TypeScript 前端、React Router、Node 24 接口服务及 SQLite。现有 3D 素材与 DEM 脚本可作数据处理参考，但展示用开放地形表面需要另加侧壁、平底和打印验证。

推荐结构：

```text
川衡 React 工具页面
  上传 GPX / 地图取景 / 调整参数 / Three.js 预览 / 下载
                  │
                  ▼
现有 Node API
  登录与权限 / 创建任务 / 查询状态 / 受保护下载
                  │
                  ▼
独立 Node 生成服务或进程
  GPX 解析 → DEM provider → 投影与采样 → 实体网格 → 检查 → STL/3MF
                  │
                  ▼
任务记录、DEM 缓存、临时输出与预览
```

- 几何核心接受统一参数，脱离 Vue、React、Electron 和数据库；以后可替换网页界面或计算引擎。
- 第一版个人工具在当前项目开发，与川衡主站通过接口连接，便于单独测试。
- 正式接入新增建议路由 `/tools/terrain-print`，沿用现有视觉、导航和会话。
- 模型计算进入独立进程/Worker；网页提交任务取得 ID，再查询阶段和结果。避免长计算阻塞登录、报名等接口。
- 个人验证先一个并发任务；成员开放阶段增加持久任务、配额、取消、重试和文件保留期限。
- 网页 3D 组件按需加载；桌面以预览为主要区域、参数在侧栏，窄屏按步骤展开。
- 原始路线和模型默认不进入网站公开素材目录；关联公开活动或作品展示属于单独功能。
- 地形数据缓存与每人的路线输出分开，遵守所用数据集的来源标注要求。

## 7. 第一版验收标准

- 使用真实两步路 GPX，路线位置正确，多个段之间没有错误直线。
- 地形来自所标注的高程数据，缺失数据不会被静默伪造。
- 模型有平底、封闭侧壁和可打印路线；下载文件可以在切片软件按预期毫米尺寸打开。
- 预览、导出和重新打开模型的范围、比例和路线位置一致。
- 参数可重复生成；修改模型长边、路线宽度或地形高度会改变真实输出几何。
- 分色版地形与路线能以正确相对位置导入，不依赖手动重新对齐。
- 空文件、损坏 GPX、下载失败、区域过大和任务取消有明确状态。
- 实物打印作为进一步验证：检查线条是否断裂/粘连、地形是否清楚、底座是否平整，再调整参数。
