修订日期：2026-10-08。状态：完成文档与源码流程研究，尚未运行上游程序、生成真实样品或修改川衡网站代码。

## 1. 本次修订的核心决定

以 TrailPrint-3D 为确定的开发基线，沿用其现有参数、地图、地形、路线嵌件、托盘、预览和 STL ZIP 流程。开发工作集中在复现验证、必要缺口修复、网页适配以及川衡接入。

| 原初稿安排 | 修订后安排 |
| --- | --- |
| 多个项目继续选型 | 固定 TrailPrint 版本，验证已有完整流程 |
| 首版先开发一个合并实体 STL | 首版保留山体、路线、托盘三个 STL 的 ZIP |
| 后一轮再新增独立路线和分色 | 首版保留独立路线几何及分件设色能力 |
| 从头搭建网页地图与三维预览 | 先复用 Vue/Pinia/Leaflet/Three 组件，替换通信层 |
| 为接入 React 站点先重写 React 界面 | 先做独立 Vue 网页工具，同源接入川衡；React 迁移为后续选择 |
| 第一版包含本地 GeoTIFF/3MF 等 | 与上游复现分开列为增强任务 |

最终目的保持不变：导入两步路 GPX 后，自动生成山地地形与突出路线的可打印文件。已经确认的使用顺序是个人验证 → 川衡网页接入 → 协会成员使用。

## 2. 首版成品与交付契约

用户下载一份 ZIP，内含打印文件：

| 文件 | 保留的功能 |
| --- | --- |
| `Terrain_Main.stl` | 有实体底厚的山体，表面具有路线槽 |
| `Trail_Line.stl` | 独立路线嵌件，顶面贴合山体并具有可调突出高度 |
| `Tray_Base.stl` | 有边框、凹槽和装配间隙的托盘 |

ZIP 是下载包，实际供切片软件读取的是里面的 STL。三个部件可分别打印后装配；山体和路线的多材料切片方式需要在样品阶段验证，并提供对应导入说明。

首版另外附生成参数、数据来源、尺寸和装配说明。原上游 ZIP 主要交付 STL，这些说明文件是我们增加的轻量交付信息。

特别要区分：原 STL 有各自打印/建模坐标，三维预览另有装配 Z 偏移。不能声称三个文件直接同时导入就已经保持完整装配关系。先明确分别打印方式；后续可增加带装配或打印排布的 3MF。

格式优先级：

1. 保留二进制 STL＋ZIP，先复现已有产物。
2. 增加 3MF，便利分件组合、单位和设色，不改变已验证几何。
3. 合并 STL、STEP/STP 按实际需要单独评估；不作为上游复现或网页首版的门槛。

## 3. 沿用原项目的用户流程

```mermaid
flowchart LR
    A[导入 GPX] --> B[地图取景与山体尺寸]
    B --> C[地形与路线参数]
    C --> D[托盘与装配公差]
    D --> E[三维预览]
    E --> F[生成 STL 三件套]
    F --> G[下载 ZIP]
    G --> H[切片、打印与装配]
```

- 导入后自动定位，显示轨迹名称、点数和里程。
- 2D 地图上调整位置、缩放和旋转；圆形、矩形、正多边形及圆角沿用现有实现。
- 三维预览沿用原模态窗口和 Three 组件；网页显示任务阶段、错误和下载状态。
- 参数预设保存沿用现有能力。预设不含 GPX、Key 和地图取景，因此完整任务复现另存冻结快照。
- 取景和尺寸说明应以当前源码为准，而非沿用过时文档中的所有描述。

### 五个核心模块与首版参数

| 模块 | 沿用参数 |
| --- | --- |
| 地图与尺寸 | 形状、半径/长宽/边数边长、圆角、中心、缩放、旋转 |
| 主山体 | 基础底厚、垂直放大、DEM 数据集、网格精度、平滑 |
| 路线 | 简化开关、宽度、槽深、突出高度 |
| 托盘 | 总厚度、下陷深度、边框宽度 |
| 装配 | 路线槽公差、托盘槽公差；底面磁铁孔为高级选项 |

第一轮先使用上游默认配置取得可比较样品，再根据打印和性能测量调整默认值；不能把原高精度 `studio` 档未经测量就设为多人网站默认。

### 尺寸与公差必须解释清楚

当前代码以输入尺寸决定山体轮廓，托盘向外增加槽公差和边框。矩形含框尺寸为：

`成品长/宽 = 山体长/宽 + 2 × (托盘公差 + 边框宽度)`

页面同时显示“山体尺寸”与“含框成品尺寸”，按成品尺寸判断打印平台能否容纳。

路线实体宽度保持输入值，槽宽为：

`槽宽 = 路线宽度 + 2 × 路线公差`

## 4. 生成核心：保留已有调用链

```text
GPX 内容 + AppConfig + 地图视口快照
  → 校验与取景适配
  → DEM 下载/缓存/GeoTIFF 采样
  → 高程缺值处理、平滑、相对高度与毫米缩放
  → 保存挖槽前地表高度场
  → 路线投影、重采样、平底槽、独立路线件
  → 山体闭合网格、托盘及公差结构
  → 几何检查
  → 二进制 STL + ZIP
```

优先复用：

- `shared/types/` 与 `shared/utils/` 的参数、投影、轮廓、路线和装配工具。
- `electron/main/terrain/` 中的 DEM、采样、平滑和地形服务。
- `electron/main/tray/` 中的托盘生成。
- `stl-writer.ts`、`zip-packager.ts` 与导出服务中的模型生成部分。
- 已有相关断言测试与验证脚本；区分真正断言和仅输出统计的脚本。

当前固定槽底是 `-trailDepthMm`，地形底面是 `-baseSolidThicknessMm`。路线件从同一槽底延伸到原地表加突出高度。保留这一结构，先验证打印配合。

预览和导出存在不同计算路径，导出还可能自动调整取景。每个任务必须冻结配置、视口与最终计算选区，显示实际采用的范围；最终检查基于导出实体。实际高度受上游质量档高度上限影响时，要记录压缩后的高度，避免只显示名义放大倍数。

## 5. 必须补做的有限工作

这些工作来自本轮源码核对，范围是明确缺口与网页边界。

### 打印与轨迹正确性

1. GPX 解析保留多个轨迹段，支持标准 XML/命名空间，避免段间误连。
2. 路线离开取景区又重入时保留多个有效线段，投影、挖槽和路线生成保持一致。
3. 校验山体底厚减槽深仍满足最小剩余底厚；加强有限数值、正尺寸等参数校验。
4. 强化路线实体质量检查。上游对山体和托盘检查开放/非流形边，路线目前只要求最低三角面数量。
5. 用急转弯、交叉、往返重叠、陡坡和不同取景形状做实际导出及切片验证；出现配合问题时局部修正。
6. 分开记录 DEM 下载错误、真实缺失区域与插补；预览和说明反映所用数据及处理。

### 网页运行边界

1. 将 `window.trailPrint` / IPC 替换为浏览器接口适配器，尽量保留现有函数参数和响应契约。
2. 将 Electron 缓存路径替换为生成服务的可配置目录。
3. 将“生成 ZIP”和“桌面保存 ZIP”分离；服务返回下载资源，浏览器执行下载。
4. 去掉全局“最近一次 GPX”回填，每个任务带完整轨迹或有归属的上传资源 ID。
5. 增加真正的单并发任务执行器和独立计算进程；原主流程并未通过一套完整后台队列。
6. 对预览请求合并/限流，转发已有进度，处理失败和取消，避免参数滑动时堆积计算。

## 6. 网页与川衡的接入方案

推荐先保留原 Vue 网页工具：

```text
川衡 React 主站
  工具路由 / 登录会话 / 权限 / 网站状态
                    │
                    ▼
同源独立 Vue 工具页面（按需加载）
  原 Pinia 参数 + Leaflet 地图 + Three 预览
                    │
                    ▼
HTTP/任务适配层
  创建任务 / 进度与状态 / 预览数据 / ZIP 下载
                    │
                    ▼
独立 Node 执行进程
  复用 TrailPrint 生成核心
                    │
                    ▼
任务目录、DEM 缓存、打印文件及说明
```

- 增加普通 Vite 网页构建入口；Electron 构建作为原始参考，不要求网页用户安装它。
- 独立工具可先本机使用，再从川衡的 `/tools/terrain-print` 入口加载。
- 以同源独立子页面或延迟加载 iframe 接入，隔离原全局样式，调用现有会话接口。
- 接入后适配川衡字体、色板、按钮与导航，保留已验证功能流程。
- 若以后需要统一 React 维护，再逐步迁移控件、地图和预览；生成核心和导出保持一致。这不是网页化的前置条件。
- 现有川衡 Node API 负责登录和访问控制，计算在独立进程中进行，不占用报名等接口的执行线程。

代价是多维护一个 Vue 工具构建；收益是直接保留原项目大量成熟交互。第一阶段优先验证功能与打印产物。

高程访问采用可替换适配层。个人验证先沿用个人 OpenTopography Key；成员开放前确定符合服务规则的数据访问方式。服务端存放 Key 并不能消除个人 Key 的多人共享限制，也不应将服务 Key 编译进网页。依据：[OpenTopography 规则](https://opentopography.org/developers)。

| 阶段 | 我完成的工作 | 交付与通过条件 | 你参与的环节 |

| 2：定点修复与生成入口 | 修复轨迹分段/裁剪、参数和路线检查；分离生成与桌面保存，保留几何算法 | 无 Electron 保存对话框的 Node 生成入口，三件套及报告 | 对小样、路线和公差反馈 |

| 5：向成员开放 | 增加任务归属、持久化、并发限额、保留期限、取消与数据源方案 | 成员各自取得自己的模型文件，服务可恢复 | 决定开放对象、额度与公开展示方式 |

阶段 1 保存原版结果；阶段 2 只做有证据的局部修复。桌面版与网页版比较网格尺寸、形状、路线位置和公差，不以含时间信息的 ZIP 字节完全一致为目标。

无需在复现阶段重新开发上游任务 00–08。按它的模块顺序查验和复用，在上面阶段补网页必需工作。

## 8. 首版验收

- 原三件套名称、职责和毫米尺寸保持明确，完整路线在正确山体位置。
- 分段和裁剪重入没有虚构连线，槽底保有实际底厚。
- 地形、路线和托盘通过几何检查，实际 STL 可在目标切片软件打开。
- 展示山体尺寸及含框尺寸；记录预览采用的配置和最终打印几何。
- 公差测量与小样确认山体能放入托盘、路线能嵌入槽。
- 默认 ZIP 附分别打印/多材料导入/装配坐标说明，不能要求用户猜测对齐方式。
- 相同核心、参数、取景及数据生成的桌面和网页模型一致；真实修复引入的差异单独记录。
- 网页任务失败或取消有明确状态；个人版不会使用上一任务的轨迹数据。
- 实物打印后再收敛线宽、槽深、突出高度、底厚、网格档位和公差。

## 9. 保留的扩展及未决事项

首版先关闭喷漆、翻模、NFC/LED 等扩展；其已有代码保留，启用时另做运行验收。底面磁铁孔可在基本三件套通过后增加，但不承诺文档里尚未落地的山体配对磁吸孔。

新增扩展明确包括：3MF、合并 STL、STEP/STP、本地 GeoTIFF、新 DEM provider、纪念文字、完整项目保存。其他开源项目仅作为遇到明确缺口时的参考，不再成为当前选型步骤。

下一阶段需要一份实际两步路 GPX；切片/打印验证时确定打印机或代打方式、切片软件、目标尺寸与单色/多色方式。成员开放前再确定公开部署与资源额度。
